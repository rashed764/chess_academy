# CHESSMIND ACADEMY — ARCHITECTURAL DECISIONS (ADR)

## ADR-001: Selection of Core Chess Rules Engine
- **Context:** The application requires 100% accurate, authoritative chess rules validation (including en passant, castling rights, threefold repetition, and promotion).
- **Decision:** Use `chess.js` (v1.0.0-beta.6+).
- **Rationale:** `chess.js` is the battle-tested standard for TypeScript chess applications. It executes synchronously in milliseconds, avoids network roundtrips, and prevents LLMs from inventing illegal moves.
- **Consequences:** All moves entered by students or generated by AI must pass through `chess.js` validation before modifying game state.

## ADR-002: Zero-Dependency High-Fidelity SVG Chessboard
- **Context:** Third-party React chessboard wrappers frequently have React 19 peer-dependency conflicts and opaque DOM structures that hinder Playwright snapshots and custom SVG arrow overlays.
- **Decision:** Build a dedicated, lightweight, accessible SVG/Tailwind Chessboard component with standard classical piece geometry, coordinate marks, tap/drag-to-move, and animated SVG arrows.
- **Rationale:** Ensures flawless React 19 compatibility, zero external bundle bloat, responsive rendering down to mobile screens (390px), and direct control over square highlights and tactical arrows.

## ADR-003: 5-Layer AI Teaching Pipeline
- **Context:** LLM models cannot be allowed to execute arbitrary code or mutate state directly.
- **Decision:** Enforce a strict 5-layer pipeline (Provider Adapter -> Context Builder -> Pedagogical Orchestrator -> Action Validator -> Learning Assessment).
- **Rationale:** Separates pedagogical prompts from state execution and guarantees that only verified structured actions (`HIGHLIGHT_SQUARES`, `PLAY_MOVE`, etc.) can touch the board.

## ADR-004: Dual-Tier State Persistence
- **Context:** Students must be able to explore the academy immediately with persistent local progress while also supporting full Supabase PostgreSQL synchronization when accounts are linked.
- **Decision:** Implement a repository layer (`studentStorage`) that writes to `localStorage` immediately, tracking completed lessons, XP, streaks, and puzzle ratings, with a normalized schema mapped directly to Supabase tables.
